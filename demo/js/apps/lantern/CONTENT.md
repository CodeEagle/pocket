# 《雾港末班信》内容说明

## 故事与游玩时长

《雾港末班信》是一篇约 10–20 分钟的中文短篇视觉小说。玩家是雾港灯塔站的夜班值守人。暴风雨将在午夜前封住海峡；信使 Mira 带来一封跨越二十年的信，维修师 Ren 认为旧式灯号中继已不可能使用。玩家可以调查旧档案、站台钟与屋顶透镜，决定这封信该如何送出。

故事按“开端—调查发展—风暴高潮—收束”推进。调查顺序由玩家选择；谜题和主要决定会改变可见选项与结局。剧本共有 67 行、3,507 个中文文本字符；完整调查、对白阅读、选择与演出停顿目标约 10–15 分钟。仅对白阅读会更短；直接跳过已读内容会明显缩短时长。

## 人物与内容提示

- **你**：雾港灯塔站当夜值班人。你能操作站台钟、光学中继和末班列车的信袋。
- **Mira**：在风暴前送到一封旧信的信使。她既想完成递送，也不愿让过去的人替未来承担一切。
- **Ren**：负责维修灯号中继的维修师。二十年前的一次风暴让他一直相信自己错过了警报。

内容包含风暴、海上事故的回忆、离别和未能实现的承诺；没有死亡场景或要求玩家接受单一“正确”道德答案。

## 故事节点与条件

| 段落 | 节点 | 主要状态变化 | 可验证结果 |
|---|---|---|---|
| 开端 | `arrival` | 初始化 `found_route`、`found_clock`、`found_lens`、`mira_trust`、`proof_complete`、`dial_*`、`code_misses` | Mira抵站；玩家确认末班车与风暴时间 |
| 调查 | `station` / `archive` / `roof` | 分别取得路线“7”、单响脉冲“1”、风暴记录末位“4”；选择是否听Mira解释 | 三条证据缺一时，中继盘会说明缺少线索，并回到调查 |
| 档案旧胶片 | `archive_reel_entry` | 播放原创静音三秒片段；画面只缓慢推近档案室邮路图 | 片段不设置 `found_route`，不自动完成或推进对白；玩家可用视频控件暂停、回看一秒、重播或关闭，继续剧情仍由玩家输入决定 |
| 回邮签 | `registry_open` / `registry_public_yes` / `registry_public_no` | 找到至少一条调查线索后，可登记收件人名字（1–16 个 Unicode 字符）、0–999 整数回信格和是否公开署名；逐项成功提交才写入 `reply_name`、`reply_box`、`reply_public` | 无效输入停留在当前字段；取消回到调查枢纽且不写入未提交字段；该段落不改变谜题状态或结局条件 |
| 谜题 | `dial_first` / `dial_second` / `dial_third` | 玩家分别设置三位数 | 只有持有三条证据并输入 `714` 才置 `proof_complete=true`；错误码会消耗一次中继机会，可再试一次 |
| 高潮 | `signal_window` | 根据 `proof_complete` 与 `mira_trust` 显示真结局选项；风暴窗口有限 | 超时会先拉响疏散警报，人物安全，信件错过跨时窗口 |
| 收束 | `ending_truth` / `ending_train` / `ending_shelter` | 结局各自设置 CG 与音乐请求 | 跨时真结局、末班车结局、留站守灯结局 |

`memory_note` 是可复用的 call/return 片段：玩家初次在档案室或屋顶追问 Mira 时进入，第一次会讲完整回忆，再次进入会用不同对白回应记忆已被提起。音频 cue 只表达播放请求，游戏不把音频是否成功当作剧情事实。

回邮签是调查枢纽中的可选支线。它只在至少找到一条调查线索后出现，不移动开场 `start[17]` 的第一句对白，也不改变现有调查顺序、714 解谜、三个结局或末班车默认路线。姓名、整数编号和公开署名分别走文本、数字、布尔输入；`registry_recipient` 与 `registry_mailbox` 带剧情占位提示，布尔项使用明确的“是/否”确认。取消当前字段返回调查枢纽，之前已提交的字段保留，当前草稿不提交。

## 三个结局的完整操作路线

以下是从新游戏开始的人工走查路线。选项文案会在实现中保持与这些意图一致；`CONTENT.md` 记录玩法行为，不假设渲染器内部组件。

### A. 真结局：`truth_letter` CG

1. 在站台选择查看旧航线图；在档案室核对旧邮路，取得 `found_route`，读出中继端口 **7**。
2. 回站台检查停在 23:14 的钟和单响铃路，取得 `found_clock`，读出脉冲 **1**。
3. 上屋顶检查透镜与风暴记录，取得 `found_lens`，从记录“23:14”取末位 **4**。在开场查看封口，或在 `memory_note` 中选择相信 Mira，可增加 `mira_trust`；正确报码本身不会替玩家作出这个信任决定。
4. 回到中继盘，依次拨 **7 → 1 → 4**。引擎必须实际运行三次 dial choice 和条件分支；不可把正确码当静态对白。
5. 在 `signal_window` 限时选择中选择把已解码信件送回二十年前。若玩家先选错一次，使用剩余机会重新输入 **714** 仍可解锁。
6. 到达 `ending_truth`，看到 Mira 确认信件抵达，Ren 放下二十年的自责；解锁 `truth_letter` CG。

### B. 末班车结局：`dawn_departure` CG

1. 在调查枢纽直接选择末班车，或在谜题中连续输入错误码。
2. 在最终风暴窗口选择把信装入末班车的防水信袋；也可以在限时选择超时，由默认疏散分支自然导向“信留在车上”收束。
3. 到达 `ending_train`。Mira 随末班车离港，信件会被送到一个真实地址，但没有跨回二十年前；解锁 `dawn_departure` CG。

### C. 留站守灯结局

1. 到达最终风暴窗口，在限时选择中先拉警报、留在站内维持灯塔。若限时超时，则会优先疏散乘客并自动进入末班车结局；超时后不能再选择留站结局。
2. 到达 `ending_shelter`。Mira 与 Ren 将未送出的信封放进站史柜；他们没有改写过去，但一起等到天亮。

## 谜题的证据组合

谜题要求玩家把三条在不同场景中得到的事实按中继盘刻度顺序组合，形成 **714**：

| 盘位 | 线索来源 | 推理 | 数值 |
|---|---|---|---:|
| 第一位：旧邮路 | 档案室海峡邮路图 | 只有编号 7 的旧线通往灯号中继 | 7 |
| 第二位：中继脉冲 | 站台控制箱 | 旧式中继用一声确认线路，双响是封锁信号 | 1 |
| 第三位：时间校验 | 屋顶暴风记录 | 记录显示关键潮位在 23:14，面板取分钟末位 | 4 |

只有同时满足 `found_route && found_clock && found_lens && dial_1 == 7 && dial_2 == 1 && dial_3 == 4` 才设置 `proof_complete`。错误顺序不是纯提示：每次错误会切断一次灯号窗口、播放电流中断 cue，并推进剧情；第二次失败会锁住跨时选项，仍保留末班车与留站结局。

## 素材键清单

以下是 `novel.assets.json` 中的**逻辑键**，不是磁盘路径。媒体源路径与来源记录在 [ASSETS.md](ASSETS.md)；缺失资源时 UI 应如实显示错误，不得伪报播放或解码完成。

| 类型 | 逻辑键 | 用途 |
|---|---|---|
| 背景 | `station` | 站台、夜班开端、中继盘操作 |
| 背景 | `archive` | 档案室调查、邮路图 |
| 背景 | `roof` | 屋顶透镜、风暴窗口 |
| 背景 | `dawn` | 三种结局的黎明收束 |
| 角色 | `mira` | 表情 `neutral`、`worried`、`hopeful` |
| 角色 | `ren` | 表情 `neutral`、`worried`、`hopeful` |
| CG | `truth_letter` | 真结局：信穿过灯号抵达过去 |
| CG | `dawn_departure` | 末班车结局：列车穿出雾带 |
| CG | `harbor_light` | 留站结局：风暴过后仍亮着的灯 |
| 视频 cue | `archive_route_reel` | 档案支线里的原创静音胶片，源于档案室原画的缓慢推近；不是实拍或测试色条 |
| 音频 cue | `music_storm`、`music_letter`、`music_dawn` | channel `music` 的章节配乐请求；前两者循环播放 |
| 音频 cue | `roof_gust` | channel `ambience` 的屋顶风声循环 |
| 音频 cue | `station_bell`、`relay_click`、`relay_break`、`train_depart` | channel `sfx` 的铃声、拨盘成功、线路失败、列车离站请求 |
| 音频 cue | `text_narrator`、`text_mira`、`text_ren` | 可选的旁白/Mira/Ren 短合成文字提示音，复用 `effect-0..3` |

设置页提供总音量、音乐、音效和语音四个音量项，按下后以 0%、25%、50%、75%、100% 循环。总音量乘以对应类别音量得到最终增益；`music` 使用音乐项，保留频道 `__pocket_vn_voice` 的对白语音使用语音项，`ambience`、`sfx`、单次音效频道及其他自定义频道使用音效项。默认总音量为 70%，其余类别为 100%，与原播放增益一致。音量写入 `lantern.audio.mix`；调整正在播放的频道只请求更新音量，不重新播放或跳回开头。新游戏会停止当前故事音频并按新开场意图继续播放，重置本轮谜题进度，同时保留已读对白元数据。

同一设置页还提供可选的文字提示音，默认关闭，并保存在 `lantern.audio.textSoundsEnabled`。开启后，真正显示的非空白文字每至少 100ms 可触发一次对应说话人的短合成音；旁白、Mira、Ren 使用三个本地生成的 WAV cue，走已有音效音量与四个复用音效频道。逐行显全、跳读、即时文字、空白和宿主后台时不会补放积压提示音。它是短音色提示，不是朗读或 TTS。实现来源与验证见 [VISUAL_NOVEL_GLYPH_AUDIO.md](../../../../sdk/docs/VISUAL_NOVEL_GLYPH_AUDIO.md)。

## 结局回看与配乐试听

雾港纪念页在原有 CG 展示后保留三个带结局解锁条件的结局回看，并增加一项真结局解锁的“七号邮路旧胶片”回看。每个入口从对应剧本段落的真实场景指令开始；进入回看时复制当前引擎的公开变量、元数据和阅读偏好到一个临时引擎，回看期间的视频请求和变量变化不写入主存档。退出后回到打开纪念页之前的扉页或旅程位置。

纪念页还列出主故事元数据中已经记录、且仍存在于资源注册表里的音乐 cue。试听和回看配乐共享单个 `music-preview` 宿主频道；播放时暂停原有 `music` 播放器，停止试听或离开回看后继续同一个播放器，因此保留原播放进度。试听不创建 Dart 音乐状态或额外播放器池。

英语回看标题放在 `novel.locales.json` 的 `replays` 稳定 ID 表中；四项标题与入口位置都保留在 `story.json`，不改原开场对白、调查证据、714 解谜或默认末班车结局。来源、引擎隔离和真实 host 验收见 [VISUAL_NOVEL_GALLERY_REPLAY.md](../../../../sdk/docs/VISUAL_NOVEL_GALLERY_REPLAY.md)。

## 能力节点矩阵

| 引擎/产品能力 | 剧情节点 | 人工或自动验证方式 |
|---|---|---|
| 背景与角色场景调度 | `arrival`、三个调查地点、三个 ending | 查看 `scene` snapshot 的背景、角色位置、表情和 remove |
| 对白/旁白稳定回看 ID | 所有 `say` 指令 | 验证每个 `say.id` 唯一；走到不同节点检查 backlog 顺序 |
| 变量/条件/分支 | 证据收集、信任、谜题检查、结局选项过滤 | `story.test.ts` 实际执行线索缺失、错误码与正确码路线 |
| 有限时选择/超时分支 | `signal_window` | 在一次路线里 `tick` 超过 `timeLimitMs`，确认默认疏散目标和信件错过窗口 |
| Call/return | `memory_note` | 从档案与屋顶两个 caller 进入后分别返回原节点 |
| Wait/tick | 铃声、风暴进站、片尾停顿 | 小于时长时仍处 wait；达到时长后继续 |
| 音频请求事件 | 各场景 audio cue | 引擎只返回请求事件，不断言宿主播放成功 |
| 视频控制与原生事实 | `archive_reel_entry` | 非循环播放由真实视频播放器报告 ready/ended；时长已知后可暂停、回看一秒、重播或关闭。胶片自然结束不会推进对白；decoder 未初始化时不伪报完成 |
| 结局/CG解锁元数据 | `ending_truth`、`ending_train`、`ending_shelter` | 分别到达三结局并检查 ending id / cg |
| 存档、读档、回滚、已读跳过、自动模式 | 由宿主游戏 UI 提供 | UI 将调用引擎正式 API；`story.test.ts` 检查 JSON 故事导入、存读恢复、对白回滚、阅读偏好切换，以及输入阶段不会被自动/跳读/暂停时间越过 |

回看、回滚、存读档、已读跳过和自动模式属于游戏 UI 入口与引擎 API 的组合能力，不在剧情里伪造按钮或第二套历史/偏好状态。`story.test.ts` 用引擎的正式快照、选择、tick、save/load/rollback 方法走查，UI 将其呈现为可操作控制。原生输入验收另由 `demo/js/tests/novel_input_native.test.ts` 和 Flutter 系统 IME 集成测试覆盖；来源与限制见 `sdk/docs/VISUAL_NOVEL_INPUT_ACCEPTANCE.md`。

## 穿雾换景

扉页可进入独立的“穿雾换景”试映：站台从左向右、档案室从右向左、屋顶从上向下、晨景从下向上揭幕，每次 1.2 秒。对白与返回按钮固定在舞台之上，点击继续进入下一幅。沿用既有 replay 隔离，返回后原旅程保持在离开的位置；不改变既有剧情指令、v6 游标或结局。四段对白和入口有中英文本地化。运行、编辑与验收范围见 `sdk/docs/VISUAL_NOVEL_REVEAL.md`。

## 灯塔合奏

扉页新增独立回看“灯塔合奏”（英文 Lighthouse Ensemble）。六秒 `beacon_sweep` 预设共用现有叙事时钟，编排镜头推进、Mira 位移/缩放/旋转和海风、站台钟、继电器三次音效触发。屋顶场景复用同一预设；末段显式取消并回到静止构图。阅读者可以继续推进来打断演出。主故事旧指令、v6 游标和版本迁移映射不变；已有 replay 隔离保持原旅程存档。详见 [时间线实现与验收范围](../../../../sdk/docs/VISUAL_NOVEL_TIMELINE.md)。

### 合奏的第二乐章

“灯塔合奏”追加三句中英对白。镜头再次靠近屋顶，`harbor_crescendo` 让海风声道从静音渐强至 0.85，再渐弱至静音；钟声在两者之间越过海峡。六秒结束停止声道，提前继续或返回同样停止，不留下循环风声。音量与玩家主音量、音效音量相乘。旧指令保持原序，新段落仅追加；旧版本迁移映射不变。实现及验收见 [音量包络](../../../../sdk/docs/VISUAL_NOVEL_AUDIO_ENVELOPES.md)。
