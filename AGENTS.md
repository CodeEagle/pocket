# Pocket integration

- Flutter owns only the rendering surface, input/IME, lifecycle, resource decoding and explicitly registered native capability transport. Business UI, state, routing and component composition belong in JS.
- For new capabilities, implement all logic that can run in JS in the JS SDK. Keep Dart limited to necessary Flutter/FFI/resource IO boundaries; app policy, recording controls and orchestration must not acquire another Dart state machine. Capture native Worker/IO facts at the official native execution boundaries when JS cannot observe them accurately.
- Reuse the pinned PocketJS compiler and engine. Do not invent a second layout engine, mock runtime fallback or success placeholder.
- Work inside `/Volumes/ORICO/Development/Github/pocket`. `sdk/` is the reusable implementation and `demo/` is the only Showcase consumer. The Demo Flutter project is first-layer (`demo/lib`, `demo/ios`, `demo/android`, `demo/pubspec.yaml`); its JS/TS project is the single `demo/js/` folder. Preserve the original parent Flutter demo and the source archive; do not use the old `pocket_host` directory as a second implementation or edit it during normal work.
- Keep upstream provenance and reproducible bootstrap. Generated caches and binaries are not source.
- Validate actual JS execution and input-driven frame changes. Report unsupported components honestly.
- Source-first integration is mandatory: before implementing a capability, inspect the retained parent `/Volumes/ORICO/Development/Github/pocketjs_flutter_demo` (excluding its `pocket_host/` directory). The former `sdk/migrations` archive was deleted in the audit cleanup and is not an available source. Reuse and adapt the retained implementations and regression scenarios; do not start over. Add new code only for an evidenced gap or a necessary adaptation to the thin Flutter host / JS-owned UI architecture. Record the source paths, retained behavior, necessary changes and validation in `sdk/docs/`.
- Use ablation to remove redundant layers and duplicate state. Do not replace existing working components with speculative new wrappers or accept static checks as proof that migrated interactions work.
- Delegate new execution work to Argon Low (`agy --model gemini-4-argon-low --effort low`) first. After all implementation and validation are complete, request one consolidated Argon Medium review (`agy --model gemini-4-argon-medium --effort medium`). If the requested model is unavailable, report that fact and obtain a model choice rather than silently substituting another model. Workers must not spawn more agents. Shared workspace: never revert another worker's edits.

- Public SDK code under `sdk/` must not import `demo/` internals. Keep scaffold/editor/showcase on the same pinned buildGuest bytecode pipeline; preserve custom consumer files and keep generated platform patches idempotent.
