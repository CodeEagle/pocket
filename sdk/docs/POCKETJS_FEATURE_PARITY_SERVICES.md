# PocketJS service and runtime parity audit

**Audit date:** 2026-11-03

**Pinned source:** `sdk/.cache/pocketjs/.pocketjs-revision` = `99924de47c62fa36f526a8791055d91cbbdb3836`. `sdk/scripts/prepare_upstream.py:19-20` pins that revision and archive SHA-256 `82d5d72ca242b5827379e0e7a53114bc9ee2093af0a9306336a5def543708cba`. The extracted cache marker matches. The source archive is not retained in this checkout, so this audit did not recompute its SHA-256. The pinned patch list includes `demand-scheduler.patch` (`prepare_upstream.py:26-36`); scheduler timing is outside this report.

**Integration update:** The audit below records the pre-SystemUI baseline. The workspace now includes the JS-owned SystemUI kernel, app client, thin Flutter runtime port and app/shared JSON KV. This does not mount the upstream `fs` namespace or `ui.appLaunch` provider. See [MULTI_APP_IMPLEMENTATION](MULTI_APP_IMPLEMENTATION.md) for the new boundary and validation.

This report covers JS/runtime service bindings, plugin/capability negotiation, workers, framework/compiler and manifest integration, package updates, PAK and streamed fonts. It does not re-audit rendering, input, animation, physics, compositor, 3D or broad UI parity.

## Findings to prioritize

1. **P1 — Worker execution and worker services are absent.** The pinned build can emit a `.worker.js`, but the SDK build adapter neither returns nor copies that artifact, while the SDK runtime creates a single UI guest and installs no `__pocketWorker`. This blocks the upstream `io.http`, channels, worker timers and `io.offload` lifecycle. It also prevents streamed-font archives from loading through the standard service. Fixing only the UI bindings would leave the execution model incomplete.
2. **P1 — The service bridge is an RPC/plugin layer, not the pinned direct service API.** The SDK correctly supports bounded `host.request` calls and provider registration. It does not mount upstream `fs`, `audio`, `media`, `camera`, `offload`, `link`, `wifi` or `agent` globals. Hardware features use the separately named `hardware.*` provider contract; that is useful partial coverage, not direct API parity.
3. **P1 — The public SDK build path is Solid-only and drops resolved feature metadata.** Pinned PocketJS supports Solid, Vue Vapor and Octane, plus feature-selected builds. `build_guest.ts` forces `--framework=solid`, passes no resolved target plan, and the SDK manifest parser reads only package capabilities and permissions. MicroTS has a separate AOT compiler and is not invoked by this pipeline.
4. **P2 — Streaming font primitives are present, but the service path is incomplete.** Native `ui.fontStream*` operations are available, but the built-in SDK capability is only `text.glyphs.baked`, and there is no mounted `offload` provider for `font.open` / `font.glyphs` archive requests.

## Runtime probe and negative evidence

Ran one read-only JSONL probe against the already-built `sdk/native/target/release/pocket_probe`. It created a guest, evaluated `typeof` checks, emitted the result through `pocket._emit`, advanced one frame, and quit. It reported `undefined` for `fs`, `net`, `audio`, `media`, `camera`, `offload`, `link`, `wifi`, `agent` and `__pocketWorker`; `ui.fontStreamConfigure` and `ui.fontStreamBatch` were functions; `ui.svcOpen`, `ui.svcPoll`, `ui.svcSend`, `ui.videoOpen` and `ui.appLaunch` were undefined. The `net` result is not a parity failure by itself: upstream explicitly has no UI `net` namespace. No source test suite, full build, simulator or device run was performed.

Command used:

```sh
python3 - <<'PY' | sdk/native/target/release/pocket_probe
import json
source = "const names=['fs','net','audio','media','camera','offload','link','wifi','agent','__pocketWorker']; const modules=Object.fromEntries(names.map(name=>[name,typeof globalThis[name]])); const uiNames=['svcOpen','svcPoll','svcSend','videoOpen','fontStreamConfigure','fontStreamBatch','appLaunch']; const ui=Object.fromEntries(uiNames.map(name=>[name,typeof globalThis.ui[name]])); pocket._emit(JSON.stringify({type:'event',name:'probe.modules',payload:{modules,ui}})); globalThis.frame=()=>{};"
for command in ({"op":"create"},{"op":"eval","source":source},{"op":"frame","deltaMs":16},{"op":"quit"}):
    print(json.dumps(command))
PY
```

Other inspection commands included `rg -n`, `rg --files`, `nl -ba ... | sed -n ...`, `cat sdk/.cache/pocketjs/.pocketjs-revision`, and reads of `sdk/scripts/prepare_upstream.py` plus the old demo sources. No private keys, signing secrets or credentials were read.

## Old Flutter demo reuse check

The retained `/Volumes/ORICO/Development/Github/pocketjs_flutter_demo` contains useful source behavior, but its wrappers are not parity evidence. `lib/core/real_hardware_bridge.dart:95-125` returns permission granted after bridge failure; `:128-149` reports a preview active fallback; `:190-225` writes dummy bytes and reports a successful 4032×3024 photo. These fallback semantics were correctly excluded from the new provider, as documented in `sdk/docs/HARDWARE_REUSE.md:14-45`. Reuse the native permission/camera/BLE implementation and contract shapes only; do not treat those fabricated responses as working hardware.

Likewise, old `mini_apps/pocketjs_runtime_bundle.js:50-115` calls legacy `pocket_router_*` and `pocket_plugin_*` globals, absent from the current bridge. Old `mini_apps/syslib/pocket_syslib_ota.js:166-188` accepts a SHA string based on length and mutates in-memory state; `sdk/docs/FRAMEWORK_GUIDE.md:368-369` records why that is not current OTA or deep-link/plugin integration. Current source-of-truth is the SDK `host.request` / package update path.
