# PocketJS UI feature parity audit

## Scope and confidence

This audit compares the pinned PocketJS source with the current Flutter FFI host in this worktree. The pin marker at `sdk/.cache/pocketjs/.pocketjs-revision` is `99924de47c62fa36f526a8791055d91cbbdb3836`, matching `sdk/scripts/prepare_upstream.py:19`. That bootstrap also records archive SHA-256 `82d5d72ca242b5827379e0e7a53114bc9ee2093af0a9306336a5def543708cba` and its tracked patch list at lines 28–36. The cache is an extracted archive without its own Git metadata; `git -C sdk/.cache/pocketjs rev-parse --show-toplevel` walks up to the Pocket repository and is not a revision check. I did not redownload the archive or independently recalculate its checksum.

Host findings describe the current worktree, including the in-progress native glyph projection, demand scheduler, and physics/compositor binding changes. The audit did not run the full Rust, Flutter, device, or simulator suites. I ran two narrow offline Rust probes against the pinned core from a temporary project under `/tmp`; commands and outputs are recorded at the end. Source test locations are evidence that coverage exists, not claims that this audit ran those tests.

Status labels:

- **Implemented; source test exists**: the contract and host path are present and a relevant test is in source; this audit did not execute it.
- **Implemented; host end-to-end unverified**: code paths exist, but this audit found no relevant integration run.
- **Partial**: a documented subset is present or a field/host behavior is lost.
- **Absent in this Flutter host**: the generic contract exists, but this embedding does not register a provider or feed the data.
- **Other pipeline by design**: a capability exists elsewhere in PocketJS or in the generic runtime, but this Flutter FFI path does not promise it.

## Native UI contract and styles

The native retained tree has four node types: view, text, image, and surface (`contracts/spec/spec.ts:35-42`). This is the wire-level UI tree, not the high-level framework component catalog. The v1 property set covers flex layout, spacing, wrapping, absolute offsets, overflow, z-order, hit-pass/containment, fill/gradient/border/bevel, text font/alignment/line height/tracking, 2D and limited perspective transforms, arcs, and skew (`contracts/spec/spec.ts:323-435`). Percent sizing is only the full-parent sentinel; other percentages and full web CSS are not part of this ABI (`spec.ts:68-74`).

Compiled style tables support base/focus/active variants, transitions, and baked keyframe timelines (`contracts/spec/spec.ts:967-1050`). Core tests cover style transitions and fixed-step explicit animation (`engine/core/src/tests.rs:506-590,1454-1520`) plus baked timelines, fills, loops, and precedence (`engine/core/src/tests.rs:2146-2280`). These are actual core features; do not recreate them as Flutter widget animations. They have source coverage but were not run by this audit.

The pinned framework deliberately exposes composition primitives over the retained UI contract; the current `pocket_ui` layer says it is not a full second widget catalog (`sdk/packages/pocket_ui/src/ui.tsx:1-8`). Missing web widgets or the old demo's 38 labels are not missing native node opcodes.

## Assets, image formats, sprites, SVG and DeepZoom

- Package installation maps `ui:styles`, `ui:font.*`, `ui:img.*`, and `ui:sprite.*` to core assets; sprite frame metadata is retained (`engine/runtime/src/assets.rs:8-54`). Image upload/rendering and sprite registration use the pinned core ops and framework primitives (`contracts/spec/ui-ops.ts:94-110`, `framework/src/primitives.ts:67-77,140-148`).
- The Flutter PAK decoder converts PSM 5650, 4444, 8888 and T8+palette into RGBA (`sdk/packages/pocket_flutter/lib/src/pocket_assets.dart:63-100`). Native resource snapshots are cached by texture revision (`sdk/native/src/lib.rs:1955-1984`); Flutter copies changed borrowed frame bytes before parsing (`sdk/packages/pocket_flutter/lib/src/pocket_runtime.dart:700-749`). This avoids unchanged resource retransmission, but it is not zero-copy from the core texture through Flutter's GPU image.
- SVG support is an offline asset baker, not a runtime SVG renderer. It accepts a limited shape/path subset; elliptical path arcs fail (`framework/compiler/bake-svg.ts:1-17,202-210`), group transforms are rejected (`bake-svg.ts:345-355`), and only circle, rect and path elements are scanned (`bake-svg.ts:356-360`). Bake icons before runtime. The current graphics helper explicitly retains SVG specs and does not claim a 3D/particle renderer (`sdk/packages/pocket_ui/src/graphics.ts:1-10`).
- DeepZoom and tileset streaming are present upstream: the framework budgets tile loads per frame and keeps its demand loop continuous only while work, motion or interaction remains (`framework/src/deepzoom.ts:97-117,498-525`); tiles use package-backed native loading with a browser fallback (`framework/src/tiles.ts:1-16,104-146`). The core decodes one tileset tile into T8 or RGBA textures (`engine/core/src/lib.rs:1168-1210,2694-2745`). The pinned Zoom Lab exercises the official component (`apps/zoomlab/app.tsx:1-30`). This is not a new Flutter component to duplicate. Source wiring is present; this audit did not run a Flutter end-to-end DeepZoom interaction.

## Bindings, animation, physics and font streaming

Generated operations are not all unconditionally mounted. The RquickJS guest installs only operations permitted by the binding profile and supported by the active OpContext (`engine/guest-rquickjs/src/lib.rs:341-352`). Provider slots start empty and compositor/physics gates start false (`engine/runtime/src/lib.rs:82-97`); package tile loading requires installed package data, compositor operations require the compositor gate, auxiliary hit tests require an auxiliary viewport, physics ops require the physics gate, and provider ops require an added provider (`engine/runtime/src/lib.rs:182-231,243-260`). A source contract entry alone is not evidence the Flutter guest sees that JS function. The guest binding test explicitly checks that unregistered service/video/application providers are omitted (`engine/guest-rquickjs/src/lib.rs:714-725`).

The current FFI host enables physics and compositor before bundle mount (`sdk/native/src/lib.rs:2889-2897`). Auxiliary output is an opt-in logical viewport set before guest load (`sdk/native/src/lib.rs:3120-3183`); PocketView exposes the matching property (`sdk/packages/pocket_flutter/lib/src/pocket_view.dart:278-282,694-710`). Core creates an independent auxiliary tree and DrawList, rendered below the primary in a scrollable column by this Flutter host (`pocket_view.dart:3270-3330`). This is a logical second output preview, not a physical second display.

Physics gate and limits: OpContext.set_physics_enabled is the low-level enable API (`engine/runtime/src/lib.rs:176-180`); generated physics operations are 52–56 (`contracts/spec/ui-ops.ts:159-169`) and supports_op hides them until that gate is true (`engine/runtime/src/lib.rs:211-231`). Before the current FFI enable call, the minimal guest probe `typeof ui.physicsCreate === 'function' && ui.physicsCreate(1, new ArrayBuffer(0)) > 0` would fail because RquickJS omits unsupported operations; with current host setup it should pass, create a world, then permit `ui.physicsDestroy(world)`. The FFI smoke test source does that create/destroy and checks no pending work remains (`sdk/native/src/lib.rs:4111-4127`); this audit did not execute it. The implementation is bounded: world substeps clamp to 1–8 (`engine/core/src/physics/mod.rs:436-469`), bodies accept at most 4 retained views, emitters at most 64 particles and 16 textures, and chains/zones at most 32 points (`contracts/spec/physics.ts:384-389`, `core/src/physics/mod.rs:472-512`); events retain at most 128 records per tick and eight ticks of backlog (`physics.ts:327-333`). Handles use generation-tagged slots with a bounded encoded slot index (`core/src/physics/mod.rs:145-189`).

Core font-stream operations are available, but end-to-end streamed font loading uses service requests such as `font.open` and `font.glyphs` (`framework/src/fonts.ts:151-163,209-234`). The Flutter host has no generic service provider for `svcOpen/Poll/Send` (`contracts/spec/ui-ops.ts:127-138`, provider registration required by `engine/runtime/src/lib.rs:182-204`). Baked package font atlases work; do not describe all font streaming core ops as absent, but do describe external font archive service loading as unavailable through this host.

## Auxiliary outputs, compositor surfaces and 3D

- Generic Runtime supports multiple renderer/display registrations (`engine/runtime/src/lib.rs:465-484`), but the current FFI host returns one primary DrawList plus an optional auxiliary DrawList. Generic multi-display composition is a separate runtime/presenter path, not an implemented Flutter capability.
- The current host maps one Pocket Flutter package surface to one explicit handle before guest evaluation (`sdk/native/src/lib.rs:856-873`). The extension bridge permits a bounded set of Glass or already-authorized platformTexture surfaces (`native/src/lib.rs:788-834`; texture authorization is in `pocket_view.dart:50-60`). This is host-backed texture composition, not arbitrary native widget embedding. The host also maps its custom video op to Flutter video_player textures and pauses/releases hidden video (`pocket_view.dart:1611-1687,1865-1930,3393-3414`); generic video provider ops remain unregistered.
- The retained UI contract includes rotateX/rotateY/translateZ/perspective. Core projects retained image quads into textured triangles; Flutter paints those triangles through Canvas (`contracts/spec/spec.ts:414-420,1460-1472`, `native/src/lib.rs:2380-2471`, `pocket_view_painter.dart:374-406`). This is limited 2.5D UI perspective, not a general scene graph.
- A separate Pocket 3D engine exists under `sdk/.cache/pocketjs/engine/pocket3d`, with renderer/camera/scene modules and platform backends, but the Flutter FFI host and Canvas painter do not link that renderer. Treat full 3D scenes as another backend/pipeline by design; adapt that engine if product scope includes 3D, rather than adding fake 3D component wrappers to the Flutter UI layer.
- The compositor core test covers z-order, clipped surface bounds and focus (`engine/core/src/tests.rs:432-474`). The native host now has a reported focused clip-projection test (`sdk/native/src/lib.rs:4531+`). The SURFACE_QUAD focused-flag loss remains outside these clip tests.

## FPS, energy and response

The current worktree has the right low-work idle shape:

- Demand scheduling uses continuous fallback when guest state cannot prove idleness, and a known idle snapshot can sleep until the next deadline (`sdk/native/src/demand.rs:61-151`). PocketView stops the ticker and schedules the next timed wake when the runtime proves a positive delay; lifecycle pause cancels it (`sdk/packages/pocket_flutter/lib/src/pocket_view.dart:1010-1049`). Treat this as implemented in source and still subject to parent integration verification; do not report the scheduler as wholly missing.
- The delta-aware binary frame path returns no frame bytes for an unchanged retained DrawList with no transient data; Flutter copies changed borrowed bytes immediately (`sdk/native/src/lib.rs:3964-4015`, `pocket_runtime.dart:700-749`).
- Texture resources are resent only when texture handle/revision changes (`sdk/native/src/lib.rs:1955-1984`). Pointer ingress has a numeric duplex path, avoiding one JSON message per high-rate pointer sample.
- Flutter currently paints retained Canvas ops in blocks behind RepaintBoundary and processes each operation with Canvas save/restore and clip (`sdk/packages/pocket_flutter/lib/src/pocket_view.dart:3429-3457`, `pocket_view_painter.dart:319-334`). Triangle ops allocate Vertices in the painter (`pocket_view_painter.dart:365-405`). These are profiling candidates for dense scenes, not a proven frame-time bottleneck. No FPS, energy, or latency benchmark was run.
- Before replacing Canvas or introducing batching, profile representative sprite, text, triangle, surface and DeepZoom scenes with the current performance harness (`sdk/packages/pocket_flutter/test/pocket_performance_test.dart`, source not run). Keep the retained DrawList, resource revision cache, no-change frame path and idle scheduler as the baseline. The lowest-risk performance path is to avoid extra wrappers and send axes/motion in batches; this audit did not measure the effect.

## Retained demo review and ablation

The old `pocketjs_flutter_demo` was inspected excluding `pocket_host/`, as required.

- The retained SVG icon specifications were already selectively adapted with provenance into `sdk/packages/pocket_ui/src/graphics.ts:1-20`; legacy line/arc command producers were removed because this renderer has no consumer (`graphics.ts:7-10`). Reuse those specs with the pinned offline baker instead of keeping a second vector command path.
- Its compatibility renderer collapses Image, Sprite, Gallery and DeepZoom into one `uiSetImageSprite` path with a fallback texture handle/frame count (`pocketjs_flutter_demo/lib/render/pocket_ui_components.dart:151-163`). Its visible Image/Sprite cards are static Flutter CustomPaint demonstrations (`pocket_ui_components.dart:1283-1376`), and its compositor/auxiliary rows are trackpad UI helpers (`pocket_ui_components.dart:1378-1408`). These do not establish current PocketJS DrawList/DeepZoom/compositor parity.
- The old canvas lab prints “0.21 ms/frame” and particle/command counts as UI strings (`pocketjs_flutter_demo/mini_apps/app_canvas_lab/main.js:5-27`); it is not a measured runtime result. Its 38-component screenshot test hardcodes an old dylib/output location and taps a separate showcase (`pocketjs_flutter_demo/test/pocket_38_components_screenshot_test.dart:82-176`). The old hardware bridge has success-shaped permission and photo fallbacks (`pocketjs_flutter_demo/lib/core/real_hardware_bridge.dart:95-125,190-225`), so it is not evidence that Flutter device sources or providers are connected.
- Ablation conclusion: do not recreate the old catalog, its placeholder surfaces, or a second renderer in the reusable SDK. The pinned four-node ABI, official framework primitives/DeepZoom, one host projection path, and the existing binary/demand scheduler are the smaller coherent system. Remaining compatibility work is TEXT_RUN alignment, SURFACE_QUAD focus propagation, and any explicitly required input/provider wiring; inline surface clipping has been adapted in the current host.
