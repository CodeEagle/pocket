# Lantern v5 collection unlock migration

Lantern v5 adds three persistent collection flags. This migration keeps the
existing save format and resumes older saves at their mapped instruction
positions; it adds no separate unlock store or save field.

## Story change

The v5 story declares `record_mira`, `record_ren`, and `record_seal` as
persistent booleans with `defaultValue: false`. It sets the matching variable
immediately before the pre-existing final `jump` in `arrival.listen_mira`,
`arrival.ask_ren`, and `arrival.check_seal`. No earlier instruction was
reordered or rewritten. New games begin with all three entries locked; replaying
one of those branches sets its persistent flag through the normal story
instruction and save lifecycle.

The project data describes the collection entries and their `unlockVariable`
references. The shared schema and projection rules are documented in
[Pocket VN data collections](VISUAL_NOVEL_COLLECTIONS.md). This file records
the Lantern save migration only; it does not claim that the shop, inventory,
or every D01 workflow is implemented.

## Native migration regression

`demo/js/tests/novel_revision_native.test.ts` loads real v1, v2, v3, and v4
autosave fixtures into the current Guest through `NativeSession`. It checks the
mapped active instruction and call return, preserves variables and progress
metadata, uses real pointer input to resume and roll back, and replays the
original choice. The v4 case additionally checks that resuming the saved Mira
call reaches the newly inserted `record_mira = true` instruction before its
existing jump.

This regression must run with an isolated v5 Guest build supplied through
`POCKET_LANTERN_GUEST_BYTECODE`, `POCKET_LANTERN_GUEST_PAK`, and
`POCKET_LANTERN_GUEST_METADATA`. It must not silently use the staged v4 Guest.

The test passed against the isolated build at
`sdk/.pocket-build/lantern-v5-collections-20261108/guest/`:

Result: **4 passed, 0 failed** across the v1, v2, v3, and v4 source saves
(3.23 seconds). The captured test output is
`sdk/.pocket-build/lantern-v5-collections-20261108/native-session-migration.log`.
Each case loaded its actual legacy save into `NativeSession`,
selected the visible continue action, checked the mapped instruction and
`arrival.listen_mira` return address, and compared variables, persistent
metadata, progress, backlog, and rollback history with the source save. It
then used pointer input to resume, roll back, reach the original
`memory_response` choice, select `trust_mira`, and reach the investigation hub
with an empty call stack. The v4 case additionally verified that continuing
the saved Mira call executed `record_mira = true` before its existing jump.

The test runs against `NativeSession`-injected storage; it does not claim that
the Flutter host's on-disk storage or device lifecycle was tested here.
