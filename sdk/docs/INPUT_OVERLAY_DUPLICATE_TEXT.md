## Change

`PocketView` now emits `textInput.opened` from the existing host-to-guest event lane after the current `FocusNode` is still attached to the mounted overlay tree. The event carries the existing input `id` and `editingSession` correlation data. `InputField` keeps its existing focus timing and uses one per-field `overlayReady` fact only to decide which layer paints the text:

- Before the matching acknowledgement, Guest text stays visible as a fallback and native text, placeholder, fill and borders are transparent. A rejected, disabled or unmounted overlay does not make the input value disappear.
- After the acknowledgement for the current session, an appearance-only update restores native colors. Only successful emission suppresses the Guest fallback; Flutter `EditableText` then paints the value, caret, selection and IME composition. The ACK does not change value revisions or selection/composition.
- Submit, outside dismissal, focus loss, route close and unmount restore the Guest fallback. An acknowledgement from a prior or closed session is ignored.

The story still owns one draft. This change adds no text copy, input policy, timer or second controller. It also does not claim a fallback can infer that an older host has mounted an overlay: a host that accepts `textInput.open` but does not return `textInput.opened` keeps the Guest fallback visible. The supported current `PocketView` returns the acknowledgement after attachment.

## First-frame appearance handoff fix (2026-11-08)

The first-frame overlap was subsequently reproduced by the root-owned Flutter driver with `小满平安归港`: its opening-frame record showed `nativeTextAlpha=1.0` while `guestFallbackVisible=true`, and the captured image showed the two copies. This supersedes the earlier statement that no pixel capture reproduced the boundary. The reproduction is evidence for the baseline overlap; candidate Flutter pixels have not yet been captured.

The retained parent still supplies the ordinary Flutter `TextField` behavior documented above, but has no acknowledgement protocol for this DrawList overlay. The fix reuses the existing `overlayReady` fact and `textInput.opened` event. A new open sends all five appearance colors (`textColor`, `placeholderColor`, `fillColor`, `borderColor`, `focusedBorderColor`) as transparent before the native field attaches. While waiting, controlled-value updates keep those colors transparent. The opened event is treated as an attachment fact: it is checked against the active input ID, route and exact editing session, but it bypasses value-revision freshness. The handler then emits an appearance-only update with the five real colors and the existing session/revision identity. It carries no text, selection, composing range or geometry, and does not advance `jsRevision`. `overlayReady` changes only after that emission succeeds. Failed, throwing or unavailable emitters leave the Guest fallback visible so a duplicate opened event can retry. A failed refresh of an already-ready session retains the mounted native editor and its ready state. Edit and submit freshness checks remain unchanged.

The existing `packages/pocket_ui/test/flutter_widgets.test.ts` now exercises pre-ACK controlled updates, an old-value-revision mount ACK, appearance-only restoration, duplicate ACK idempotence, missing/false/throwing emission, and a failed refresh of an already attached session. The standard self-contained `packages/pocket_ui/test/flutter_widgets_native.test.ts` chain passed under pinned Bun 1.4.4: it built its public widget fixture through `scripts/build_guest.ts`, then drove its QJBC through the pinned `sdk/.pocket-build/retina-native-tools-20261108/bin/pocket_probe`. It verified transparent open/pre-ACK colors, one appearance-only restore for the current session, stale-session and late ACK rejection, reopen, dismissal and submit. This is a buildGuest/QuickJS/native-event regression, not a candidate Flutter-pixel confirmation; root-owned Flutter integration will compare the candidate against the captured baseline.
